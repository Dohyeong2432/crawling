# 규제기관 모니터링 자동화

금융 규제기관 웹사이트에서 신규 자료를 수집해 담당자에게 메일로 안내하는 자동화 도구입니다.

## 프로젝트

| 폴더 | 대상 | 실행 |
|---|---|---|
| `법령_개정안_안내` | 국가법령정보센터 — 법령/행정규칙 제·개정 | `python run_check.py` |
| `법령해석_보도자료_최신자료_점검` | 금융위 법령해석 + 금융위·금감원·FIU 보도자료 | `python run_check.py 20260820` |
| `금감원_제재내역_안내` | 금감원 제재공시 | `python run_check.py 20260701` |

`금융위_법령해석_최신사례` 는 사용하지 않습니다. `법령해석_보도자료_최신자료_점검` 의 `fss_itp` 모듈이
동일한 사이트를 더 나은 형태로 수집합니다. 자세한 내용은 해당 폴더의 `_사용안함_README.md` 참고.

## 설정

이메일 발송 설정은 `notebooks/.env` **한 파일**에서 관리합니다.

```bash
cp .env.example .env
```

`.env` 를 열어 값을 채웁니다. `EMAIL_PASSWORD` 는 네이버 로그인 비밀번호가 아니라
**애플리케이션 비밀번호**입니다 (네이버 > 내정보 > 보안설정 > 2단계 인증 > 애플리케이션 비밀번호 관리).

`.env` 는 `.gitignore` 에 있어 커밋되지 않습니다. **절대 저장소나 메일에 올리지 마세요.**

## 실행 흐름

점검과 발송이 나뉘어 있습니다.

```
run_check.py   →  크롤링 + 신규 여부 확인 + 결과 출력    (메일 발송 없음)
노트북 마지막 셀 →  내용 확인 후 이메일 발송              (되돌릴 수 없음)
```

`run_check.py` 에는 `send_mail()` 을 호출하는 코드가 없습니다. 실수로 메일이 나갈 경로 자체를 없앤 것입니다.
발송은 반드시 사람이 내용을 확인한 뒤 노트북에서 실행합니다.

### 법령 제·개정

```bash
cd 법령_개정안_안내
python run_check.py            # 최근 60일 구간 재수집 후 판정
python run_check.py 480        # 소급 수집이 필요할 때 일수 지정
python run_check.py --no-crawl # 크롤링 없이 현재 DB 로 판정만
```

감시 대상은 `database/법규리스트.xlsx` 의 163건입니다. `최근발송일 < 최근개정일` 인 항목이 안내 대상이 됩니다.

### 보도자료 · 법령해석

```bash
cd 법령해석_보도자료_최신자료_점검
python run_check.py 20260820   # 이 날짜 이후 등록분만 확인
```

4개 사이트를 순회하며, 한 곳이 실패해도 나머지는 계속 진행하고 실패한 사이트를 표시합니다.

### 금감원 제재

```bash
cd 금감원_제재내역_안내
python run_check.py 20260701   # 이 날짜 이후 제재만 검토
```

관련부서와 PDF 본문 키워드로 대상을 추립니다. 검색 조건은
`py_files/common_functions.py` 의 `FIND_CATEGORIES` / `FIND_PDF_KEYWORDS` 에서 관리합니다
(노트북과 스크립트가 같은 값을 사용하므로 그 파일 한 곳만 고치면 됩니다).

## 동작 환경

- Python 3.12 (WinPython), Windows
- **Chrome 창이 뜹니다.** 대상 사이트가 클릭·다운로드 기반이라 headless 로 바꿀 수 없습니다.
  로그인된 데스크톱 세션에서만 동작하며, 무인 서버 운영은 불가능합니다.
- **Excel 이 필요합니다** (xlwings). `run_check.py` 는 창을 띄우지 않고 실행합니다.
- 주요 패키지: `selenium`, `webdriver-manager`, `beautifulsoup4`, `pandas`, `xlwings`,
  `pdfplumber`, `python-dotenv`, `pyarrow`

사내망처럼 TLS 를 중간에서 검사하는 환경을 위해 `WDM_SSL_VERIFY=0` 이 설정되어 있습니다
(`webdriver-manager` 가 드라이버를 받을 때 인증서 검증에 실패하는 문제 회피).

## 알아둘 점

**수집 창은 "오늘 − 60일" 고정입니다.** 기준점을 "DB 의 최신 공포일자"로 두면 실행할 때마다
앞으로 밀려서, 공포 후 며칠 지나 등록되는 항목을 영구히 놓칩니다
(실제로 신용정보업감독규정 2026-07-24 · 2026-08-13 개정이 이 문제로 누락됐습니다).
`table_update.py` 의 `LOOKBACK_DAYS` 에서 조정합니다.

**타법개정은 감시 대상이 아닙니다.** 국가법령정보센터의 최신법령 목록에 타법개정은 노출되지 않아
DB 에 들어오지 않습니다. 업무상 제외하기로 한 항목입니다.

**사이트 구조는 바뀝니다.** 2026년경 금융정보분석원이 조회수를 날짜 태그 안에 넣도록 변경해
날짜 파싱이 실패한 적이 있습니다. 그래서 날짜는 문자열 전체를 파싱하지 않고
`parse_press_date()` 로 날짜 패턴만 뽑아냅니다.
